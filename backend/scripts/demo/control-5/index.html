دليل المناقشة

شو تحكي وإنت عم تعرض النتيجة.

كيف أثبت إن التوزيع شغّال وإن النظام كمّل؟

ابدأ بـ9 طلبات وشوف عدد الردود من كل نسخة. بعدها شغّل اختبار الـ500، وبيّن بالجدول إن النسخة اللي وقفت صار عندها صفر ردود بعد إيقافها، والنسختين التانيات كملوا. الحاوية بترجع تشتغل بنهاية التجربة.

ليش نقلنا عدّاد تسجيل الدخول إلى Redis؟

قبل الإصلاح كان لكل Gateway عدّاد بذاكرته، وظهر HTTP 429 عند الطلب 61 في التجربة الموثّقة. بعد مشاركة العدّاد، الحدّ الافتراضي 20 طلب بالدقيقة عبر النسخ الثلاث مع بعض.

كيف منعنا تكرار البريد، وكيف وصل البث بين النسخ؟

عمّال البريد يتقاسموا طابور واحد. حجز Redis بيمنع عاملين من إرسال تأكيد لنفس الطلب بنفس الوقت، وMailpit يتعرّف على معرّف الرسالة الثابت. إشعارات Socket.IO بتنتقل عبر Redis Pub/Sub من نسخة المعالجة للنسخة اللي عليها اتصال المستخدم.
